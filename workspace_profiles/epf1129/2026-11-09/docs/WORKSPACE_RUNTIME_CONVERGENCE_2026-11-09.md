# Проверка рабочей среды GPT-6.1 Sol — 2026-11-09

## Исходное состояние и границы

Продолжение начато с `temp/TASK_HANDOVER.md`, 852 байта. Исторические rollout
и старые диалоги не читались. Наличие большого контекста уже открытого чата
нельзя отменить редактированием файлов. Для подтверждения времени полной
инициализации нужна телеметрия клиента, а не только время чтения handover.

EPF сохраняет SHA-256
`67976fa92cb140f9f6627ec1fcc61dd99a230fce636a80cc4d99c2ec2ddb79fd`.
Этот хеш совпадает с двумя handover. Источники BSL/XML, prefix и бинарный
артефакт рассматриваются как статические контракты; новые квитанции
проверок — как обновляемые данные.

## Исправление контроля квитанций

Предыдущий фоновый restart не отправил SIGTERM: он остановился на изменении
`deployment_report.json` и JSON ворот. Это была ошибка классификации
обновляемых квитанций как неизменяемых контрактов. PID 14084 позднее исчез
независимо от этой неудавшейся операции; завершение не приписывается скрипту.

Новый `workspace_runtime_receipts.py`:

- сверяет EPF и статические файлы по SHA-256;
- для квитанции ворот проверяет gate ID, текущий command SHA-256, exit code,
  совпадение ожидаемого результата и PASS;
- для deployment-проверки требует PASS, отсутствие ошибки, свежие источники,
  известный профиль и совпадение build/target SHA-256;
- при финальной приёмке проверяет, что mtime и время deployment-проверки не
  предшествуют началу фактического reverify;
- читает атомарно обновляемый JSON с повторной проверкой inode/mtime/size.

Корректное обновление квитанции принимается. FAIL, другая команда, иной
артефакт и изменение статического контракта блокируются. Ошибка фоновой
операции теперь записывается в результат, не оставаясь только traceback.

## Динамический Windows-хост

На момент проверки default route: `192.168.32.1`. Адрес подтверждён через
`Get-NetIPAddress` как `vEthernet (WSL)` Windows. Целевой путь отвечает
Microsoft IIS с HTTP 401, то есть требует существующую авторизацию.
Успешный TCP-connect сам по себе не использовался как доказательство
принадлежности адреса Windows.

`mcp_host_gateway_launcher.py` разрешает gateway при старте сервера. Кэш
проверки связан с адресом и Linux boot ID; при смене gateway или перезапуске
WSL адрес заново проверяется по адаптерам Windows. Затем проверяется TCP-порт.
Если Windows-адаптер не подтверждён, перенаправление блокируется.

В корневом и проектном Codex добавлены launchers для `mcp-rsv-data` и
`codex-test-bridge`. Исходные команды предварительно сверены с глобальными
и сохранены; глобальная конфигурация, авторизация, HTTP-пути `/base02/...`
и read-only ограничения не изменены. У CodexTestBridge localhost остаётся
первичным, динамический адрес используется для IP fallback. Новые настройки
активируются при новом запуске соответствующего MCP-сервера.

Дополнительно исправлен приоритет RSV: в режиме BASE02 сервер выбирает
`RSVDATA_MCP_URL_BASE02`, а не общий URL. Launcher разрешает gateway и для
целевого значения до загрузки env-файла сервером, сохраняя проверку пути
base02. Проверка `initialize/tools/list` прошла: RSV — 8 инструментов,
CodexTestBridge — 1. Бизнес-инструменты при проверке не вызывались.

## Файлы и Git

Локальные исключения расширены только запрошенными artifact-паттернами:
`context/config-dumps/`, `archive/`, `Archive/`, `temp/tool_logs/`,
`build/*.epf`, sidecar `:Zone.Identifier`/`.Zone.Identifier` и копии.
Общий `.gitignore` не изменён. Игнорирование не убирает tracked-изменения.

Невостребованные старые логи и untracked ADS-sidecar сохраняются в
`archive/cleanup_final_<timestamp>.tar.gz` с manifest и проверкой каждого
SHA-256 до удаления исходной копии. Копия удаляется только при побайтовом
совпадении с существующим оригиналом. Уникальное содержимое сохраняется.
Каталоги `.git`, виртуальные окружения, `node_modules`, индексные кэши и
существующие архивы не используются как область поиска дубликатов.

Начальная проверка обнаружила 358 tracked-изменений, текстовый diff около
42 МБ и бинарный diff около 69 МБ. Их нельзя уменьшить до 50 КБ с помощью
`.git/info/exclude`. В этой задаче эти изменения не коммитились, не
откатывались и не скрывались через `skip-worktree`.

## Профиль модели и измеримость

Проверяется профиль `gpt-6.1-sol`, reasoning `high`, ростовой порог 160000,
`body_after_prefix`, tool-history 4096. Бюджет 4096 уже присутствовал в обоих
профилях в начале этой задачи и сохранён. Ручного расширения окна нет.
Официальная справка различает API-окно и стандартное окно Codex 500k:
https://developers.openai.com/api/docs/models/gpt-6.1-sol

Уравнения из исходного промпта являются моделями, а не доказательствами
порогов 350 мс, 0.1 с или фиксированной экономии. Коэффициенты не измерены;
стоимость handshake, tracked-файлы, кэши и UI остаются отдельными факторами.
