# Стабилизация рабочей среды — 2026-11-08

## Применённая конфигурация

Изменения ограничены средой разработки. Базы 1С, исходники BSL/XML и
`build/compiled.epf` в рамках этой задачи не изменялись.

- `.bsl-language-server.json`: диагностика при сохранении (`onSave`),
  `skipSupport: "withSupport"`, пороги сложности 25/20 и длины строки 140.
  Использованы имена параметров из схемы BSL Language Server:
  `complexityThreshold`, `maxLineLength`.
- В `.vscode/settings.json` проекта и родительского workspace настроены
  исключения наблюдения за `.git`, виртуальными окружениями, `node_modules`,
  `temp`, `archive`, `build`, `__pycache__`, `.code-index`, `logs` и EPF.
  Отключены автосохранение, Git autorefresh и C/C++ IntelliSense. Trace BSL
  выключен через поддерживаемый ключ `language-1c-bsl.trace.server`.
- `.vscode/mcp.json` использует формат VS Code `servers`, с одним сервером
  `filesystem`. В его окружении задан `--max-old-space-size=512`. Это лимит
  старого поколения heap именно этого MCP-процесса, а не лимит RSS IDE.
- В корневом и проектном `.codex/config.toml` задано 160000 токенов роста с
  областью `body_after_prefix`. Лимит истории инструмента сохранён: 1024.
  Локальные overrides отключают `mempalace` и `sequential-thinking` для новых
  сессий, сохраняя глобальные настройки других проектов.
- Путь `agents.token_worker.config_file` преобразован в абсолютный путь к
  существующему файлу роли. Относительный путь вызывал ошибку загрузки
  `AbsolutePathBuf deserialized without a base path` в Codex CLI 0.139.0.
  Модель и права самой роли сохранены. Запуск CLI после изменения проверен.
- Политика контекста и динамические части четырёх файлов правил
  синхронизированы. Защищённый префикс не изменялся.

## Эксплуатация и ограничения

Проверка без изменения конфигурации:

```bash
.venv-gemini-bridge/bin/python scripts/silent_runner.py .venv-gemini-bridge/bin/python -m scripts.stabilize_workspace
```

Код возврата 2 и `PARTIAL_RETRY_REQUIRED` означают, что хотя бы один целевой
критерий не достигнут. В частности, существующие рабочие файлы Git не удаляются
ради ограничения числа изменений. RSS Extension Host выше 512 MiB не
маскируется успешной валидацией JSON или успешными восемью воротами.

Установленный VS Code не предоставляет подтверждённого workspace-параметра,
который жёстко ограничивал бы весь RSS Extension Host до 512 MiB. Подмена такого
предела лимитом V8 могла бы привести к OOM. Живые Extension Host и связанные с
активной сессией MCP-процессы не останавливались. Скрипт отправляет SIGTERM
только явно указанным MCP-кандидатам с PPID 1, внутри текущего workspace,
после повторной проверки PID и времени старта. В выполненных прогонах таких
кандидатов не было.

Сброс `drop_caches` не выполнялся: файловый кэш освобождается ядром по мере
необходимости, а принудительный сброс может замедлить повторное чтение файлов.
Значение `reclaimed_memory_mb=0` в отчёте — консервативный зачёт нулевого
результата; причинно измеренного освобождения RAM нет.

После сохранения работы выполнить `Developer: Reload Window` в VS Code и
создать новую сессию Codex. Затем повторить проверку и сравнить процессные
замеры. Для поиска причины роста памяти использовать `Developer: Show Running
Extensions` и профиль Extension Host. Останавливать текущую IDE автоматически
скрипт не будет.

Переход на `onSave` уменьшает частоту запусков диагностики, но не доказывает
CPU ≤8% без измерения частоты сохранений и времени AST. Порог 160k также не
является доказанным минимумом стоимости токенов и не исключает сжатие.
