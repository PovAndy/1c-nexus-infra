# Событийный контур хуков v1.3.1

## Назначение и границы

Контур создаёт детерминированную локальную обратную связь для операций
редактирования рабочей среды. Он не выполняет подключений к 1С или SQL-базам,
не изменяет данные баз и не изменяет исходные BSL/XML-модули самостоятельно.
Входной контракт — JSON из стандартного ввода; для ручной проверки допустим
путь файла вторым аргументом командной строки. Для Codex активная регистрация
находится в `.codex/hooks.json` активного корня проекта. Это необходимо,
поскольку Codex ищет `hooks.json` только рядом с активным конфигурационным
слоем текущего репозитория. После изменения декларации пользователь должен
просмотреть и подтвердить её доверие в интерфейсе Codex командой `/hooks`.

## События

| Событие | Действие | Результат |
| --- | --- | --- |
| `pre-write` | Сохраняет непустой существующий файл в `archive/backups/` через временный файл и атомарную замену. | Резервная копия до изменения. |
| `post-write` | Немедленно пропускает файлы вне BSL/XML; BSL оценивает через единый оценщик, XML проверяет на разбираемость. | При диагностическом нарушении возвращает структурированный код блокировки `2` для корректирующего цикла агента. |
| `stop-hook` | Повторно выполняет все ворота из `GATES.md`. | Успех разрешает остановку; неуспех запрещает её. После пяти одинаковых неуспехов выдаётся эскалация для человека. |
| `session-start` | Запрашивает актуализацию Graph V2. | В случае тайм-аута или занятого ресурса фиксируется отложенная актуализация без блокировки начала сессии. |
| `pre-compact` | Строит ограниченную локальную выжимку журналов. | Не раскрывает сырой журнал в контексте модели и не блокирует сжатие при собственной недоступности. |

Codex передаёт редактирование через `apply_patch` с diff в
`tool_input.command`. Диспетчер извлекает из него все целевые пути: резервное
копирование происходит до операции, а диагностика каждого BSL/XML-файла —
после неё. Одиночный `file_path` остаётся совместимым контрактом для иных
клиентов.

`post-write` не отменяет уже завершённую файловую запись: его задача —
немедленно вернуть агенту fail-closed диагностический сигнал и не позволить
считать изменение готовым до исправления и прохождения ворот.

## Диагностические правила

Для BSL применяются существующие штрафы синтаксиса, утечки временных таблиц,
некорректных конструкций и неподтверждённых метаданных. Дополнительно
блокируется вызов `Состояние()` в серверном контексте. Для XML блокировка
возникает при ошибке разбора. Состояние пяти повторов хранится локально в
`temp/.stop_hook_state.json`; временные файлы и каталоги исполнения не
подлежат резервному копированию и анализу.

## Эксплуатационные свойства

Неблокирующий путь не-BSL/XML измеряется модульным тестом без запуска нового
процесса Python. Абсолютный лимит времени для полного BSL-анализа не обещается:
он зависит от размера файла, внешнего синтаксического средства и нагрузки
хоста. Конфигурация ограничивает длительные операции тайм-аутами и оставляет
Graph V2 и ограниченная дистилляция являются fail-open действиями: их
временная недоступность не должна прерывать интерактивную сессию. Проверка
изменённого BSL/XML и `Stop` остаются синхронными fail-closed воротами.

Файл `.github/hooks/omvl-workspace.json` сохраняет отдельную совместимость с
предыдущим VS Code-контуром. Codex его не обнаруживает и использует только
`.codex/hooks.json`.

## Проверяемость

Набор `scripts/test_hooks.py` покрывает JSON-вход, резервное копирование,
быстрый пропуск нерелевантного файла, блокировку грязного BSL, успешный чистый
BSL и защиту от цикла остановки. Полная готовность контура определяется
прохождением этих тестов, проверки контрактов промптов, Graph V2 и ворот
`GATES.md`.
