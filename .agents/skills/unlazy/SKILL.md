# Доказуемое завершение

Сначала зафиксируй измеримый результат и узкие границы изменения. Для существенной задачи создай или актуализируй `GATES.md`: один заголовок `## <идентификатор>` на ворота и три поля `CHECK`, `EXPECT`, `EVIDENCE`.

- `CHECK` — только локальная команда с runner `python3`, `pytest`, `oscript` или read-only `git`; shell-цепочки запрещены.
- `EXPECT` задает `exitcode=<n>`, `regex=<паттерн>` либо оба условия; успех требует выполнения всех заданных условий.
- `EVIDENCE` расположен только в `temp/gates/`; сохраняются хеш и метаданные результата, но не сырой вывод.
- Выполни `scripts/gate_check.py --reverify` после изменения проверяемых файлов. Любой FAIL или STOP блокирует заявление о завершении.

Для декомпозиции по глубине используй `/unlazy tree N <цель>` только когда N независимых уровней действительно уменьшают риск. Каждый лист обязан иметь собственные проверяемые границы и приемочные ворота; глубина не является заменой фактической проверки.

Не устанавливай внешние Stop Hooks и не запускай обработчики с записью без отдельного согласия пользователя. Проверяющий скрипт — локальный fail-closed стоп-сигнал для агента, а не средство обхода системных разрешений. Формат и безопасные примеры реестра находятся в `references/gates-contract.md` и открываются только при подготовке ворот.
